# C++ findings from the library programs

**Status:** Fixed: 2 (lexer, parser; not `parse`/`parseInline`), 4, 5, 8, 9, 10, 12 (but `createColumnHelper().accessor`), 18, 20, 21.

1. katex (awkward): a caught `ts::Error` converts to nothing generated: `ParseError` extends the generated global `::Error`, not `ts::Error`. To use `ParseError::length()` on a caught error, copy the handle: `static_cast<ts::Handle&>(pe) = caught;` (`ParseError(ts::handle, e.h)` would double-release).
2. marked (can't express): function-typed consts (`marked.lexer`, `parser`, `options`, `setOptions`, `walkTokens`) are bound as bare `ts::Callback` structs (e.g. types/string_MarkedOptions_to_TokensList_fn.hpp): constructible from a lambda but with no way to call them. `marked_ns::get_parse()` is a `ts::Value`, and the `parseInline` const (callable object type) has struct `parseInline` with `invoke` but no accessor to obtain it. Used `Lexer::lex_static` and `Marked::parse()/parseInline().invoke` instead.
3. marked (can't express): the `Token` union (bindings/types/Token.hpp) declares `ts_raw_Token_tag` but defines no `decode_Token`, so `ts::Array<Token>` fails to compile (`ts_runtime.hpp:205 no matching constructor for variant`), and `TokensList` iteration/`at()` yield untyped `ts::Value`. Workaround: rewrap the value as `Tokens_Generic` to read `type()`, then as the specific token type, via handle copy.
4. marked (runtime bug): `get_markedInstance()` (areas/main/functions.hpp, main.cpp) reads `markedInstance`, which marked.d.ts declares but does not export: null at runtime ("Cannot read properties of null (reading 'lexer')"). Used `Marked::create`.
5. marked (runtime bug): a renderer callback with a rest parameter `...args: [Tokens.Heading]` (types/MarkedExtension_renderer_heading.hpp:16) is typed to take `ts::Tuple<Tokens_Heading>` decoded with `from_handle`, but glue.mjs:325 calls it with the token as its first argument, spread: `args.get<0>()` is null. Worked around by reading the Tuple's handle as the heading.
6. date_fns (awkward): `isValid(date: any)` is bound as `isValid(ts::Value)`, and a `Date` (or any generated class) does not convert to `ts::Value`; the handle must be copied by hand (`ts::Value v; static_cast<ts::Handle&>(v) = date;`). Same for any `any`/`unknown` parameter. Also generic functions with constrained parameters (`closestTo`, `eachDayOfInterval`) cannot deduce them (`requires ts::extends<...>`): the type arguments must be spelled, `closestTo<Day, ts::Array<Day>>(...)`.
7. node (can't express): `readFileSync(path, "utf8")`, `Buffer::toString(enc)` and write options take `global_BufferEncoding` (ts_types.hpp:561), an opaque handle struct, not the generated `BufferEncoding` enum (ts_types.hpp:8) and with no constructor from a string. Worked around with a raw `global_BufferEncoding(ts::handle, ts_raw_js_from_string("utf8", 4))`. (readFileSync(path) returning a Buffer works.)
8. node (runtime bug): every `path::` function throws "Cannot read properties of undefined (reading 'join')": glue.mjs:389 calls `PK["path"].path.join(...)`, but `import("node:path")` (what impl.mjs binds) has no `.path` member. No path:: call could be tested.
9. node (runtime bug): `mkdir_options` (areas/main/mkdir_options.decl.hpp) has `static constexpr double recursive = true;` for the .d.ts literal `recursive: true`, but `mkdir_options::create()` (glue.mjs:365) gives `{}`, so `mkdirSync(p, mkdir_options::create())` is not recursive and fails with ENOENT. (Also a literal `true` typed `double`.)
10. node (runtime bug): a listener typed `(...args: any[]) => void` (`any_array_fn`, types/any_array_fn.hpp) is decoded as `ts::Array<>` from a0, but glue.mjs:345 `(a0) => f(ctx, ref(a0))` passes only the first argument: `emit("ping", 5, "x")` hands the listener the number 5 as an Array handle (reading it throws). Same rest-parameter mismatch as 5. Also awkward: EventEmitter methods have an undeducible `template <class E>`, called `emitter.on<void>(name, fn)`, and event names are `ts::Value::string("x")`.
11. three (can't express, as written): `Vector3::add`, `dot`, `lerp`, `Box3::expandByPoint`, `Vector3::applyQuaternion`, `Quaternion::setFromAxisAngle`... take the interfaces `Vector3Like` / `QuaternionLike` (areas/main/Vector3Like.decl.hpp), and a `Vector3`/`Quaternion` is one structurally in TypeScript but not in the bindings (`no viable conversion from 'Vector3' to 'Vector3Like'`; ts::bases<Vector3> is empty). Every such call needs a hand-made `Vector3Like l; static_cast<ts::Handle&>(l) = v;`. Everything else in three (Group/Mesh where an Object3D is wanted, default template arguments, Raycaster) worked.
12. tanstack_table (can't express + runtime bug): table-core v9 declares its API as function-typed properties (`getRowModel: () => RowModel`, `getColumn: (id) => Column`, `row.getValue`, `column.toggleSorting`, `table.setSorting`, `helper.accessor`...). The bindings give them as `ts::Callback` structs (types/Table_RowModels_getCoreRowModel.hpp, string_to_TValue_fn...) with a constructor from a lambda and no way to call them; and the property getter returns the bare function, so even a caller loses `this` (prototype methods such as `row.getValue` throw "Cannot read properties of undefined (reading '_valuesCache')"). Driven only by calling through `callMemoOrStaticFn(obj, "name", staticFn, args)` (a method call) and `functionalUpdate(fn, x)`: library helpers used as trampolines. `createColumnHelper().accessor(...)` has no such route; column defs were plain objects. Same root cause as 2 (marked) for all function-typed consts.
13. tanstack_table (can't express as given): `constructTable` requires `features.coreReactivityFeature` (atoms); the package offers it via `renderPhaseReactivity({createAtom, batch})` (needs @tanstack/store) or the subpath `@tanstack/table-core/store-reactivity-bindings`, neither in impl.mjs `modules` ("Cannot read properties of undefined (reading 'wrapExternalAtoms')"). The program implements the atoms (get/set/subscribe objects) in C++ with callbacks; a real user could not.
14. tanstack_table (can't express): `readonly` interface properties get a getter and no setter (`TableOptions_Table::features()`, `data()`, `atoms()`... areas/main/TableOptions_Table.decl.hpp), so the options object of constructTable cannot be filled through the typed `TableOptions_Core`; it was built as a `RowData_map` (an index-signature interface, `{}` with `set_at`) and its handle rewrapped. `ts::Value` has no object constructor and a generated handle does not convert to `ts::Value` (`val()` helper).
15. pixi (can't express): generic instantiations do not convert: `Texture<BufferImageSource>` (what `Texture::WHITE()` returns) is a `Texture<TextureSource<any>>` in TypeScript, but `Sprite::from(Sprite_from_source(Texture<BufferImageSource>::WHITE()))` fails ("no matching conversion for functional-style cast ... to 'Sprite_from_source'"); the handle was rewrapped by hand.
16. pixi (can't express): `Container` extends `EventEmitter<ContainerEvents, any>` from eventemitter3, which is not bound: the generated `EventEmitter` (ts_types.hpp:2328) is an empty struct, so `on`/`off`/`emit` ("no member named 'on' in 'Sprite'") exist on no display object, and pointer/scene events cannot be listened to.
17. pixi (can't express, as 11): `ApplicationOptions.canvas` is `ICanvas`, an interface an `HTMLCanvasElement` satisfies, but there is no conversion (`no matching conversion for functional-style cast from 'HTMLCanvasElement' to 'ICanvas'`). Also awkward: `Application_init_options::backgroundColor()` returns `std::optional<ts::Value>` while its setter takes `std::optional<ColorSource>`.
18. echarts (runtime bug, can't express; same class as 9): `BarSeriesOption::type` is `static constexpr std::string_view type = "bar"` (the literal discriminant), but `BarSeriesOption::create()` makes `{}` without it and there is no setter, so `setOption` with a series built from it fails ("[ECharts] Unknown series undefined") and, the exception happening inside echarts' main process, every later call fails too ("`setOption` should not be called during main process"). The same holds for every series/axis type with a `type` literal. Worked around with `Dictionary<ts::Value>` (`{}` with `set_at`) for the series. Also awkward: `EChartsOption::xAxis()` reads `std::optional<ts::Value>` while its setter takes the typed union `EChartsOption_xAxis`; reading a series back means rewrapping a Value handle as `ts::Array<>`/`BarSeriesOption`; `Eventful::on` has an undeducible `template <class Ctx, class EvtNm>` (`chart.on<ts::Value, std::string>("custom", fn)`).
19. konva (can't express): generic base instantiations do not convert, so `layer.add({rect})` does not compile: `::Rect` is a `::Shape<RectConfig>` while the union is `Group_or_Shape = variant<::Group, ::Shape<ShapeConfig>>` ("no matching conversion for functional-style cast from '::Rect' to 'Group_or_Shape'"), and `layer.find<::Rect>(...)` fails its `requires ts::extends<ChildNode, ::Node<NodeConfig>>` (Rect's chain is Node<RectConfig>). Rewrapped handles; `find<::Node<NodeConfig>>`. Same family as 15 (pixi).
20. konva (runtime bug): the `GetSet` properties (`rect.x()`, `width()`, `fill()`, `id()`, `name()`... returning `GetSet<T, This, SetType>`, a callable object) are unusable: glue.mjs:353 `Node_get_x` returns `get(self).x`, the bare prototype method, and `GetSet_invoke` (glue.mjs:399) calls `get(self)()` with no receiver: "Cannot read properties of undefined (reading 'getX')". Same loss of `this` as 12. Worked around with `getAttr<Config, std::string>("x")` / `setAttrs(config)`.
21. konva (runtime bug, blocks the whole library): `new (PK["konva"].Stage)(...)` (glue.mjs:322, and every class) fails with "PK.konva.Stage is not a constructor": konva's d.ts is `export default Konva` (an object holding the classes) and the module impl.mjs binds, `import("konva")`, has only a `default` key (the glue would need `PK["konva"].default.Stage`). With the glue patched to `.default`, the full program passes (61 checks). tests/libraries/konva/test.cpp therefore probes with `Layer::create()`, checks the "not a constructor" error and returns; it runs the full program once that works.
22. prosemirror (can't express / awkward): `Node.fromJSON(schema, json)`, `SchemaSpec.nodes/marks` (OrderedMap | Record) take `ts::Value`/`object`, and a C++ program cannot make a plain JavaScript object or an array of values from nothing (`ts::Value` has number/bool/string only): `Attrs`/`NodeSpec`/`MarkSpec` (index-signature interfaces, `{}` plus `set_at`) were used as dictionaries and their handles rewrapped as `ts::Value`. Same need in tanstack_table (14) and echarts (18). A generic `ts::Object` would remove it.
23. prosemirror (can't express): `HTMLElement` and `Element` are empty structs in the prosemirror bindings (no lib.dom members: `no member named 'textContent' in 'HTMLElement'`), so the rendered DOM cannot be inspected; `EditorView::create(place, props)` takes `variant<dist_DOMNode (empty), ...>` and an `HTMLElement` (the page element) does not convert (rewrapped). `view.dispatch` is a `Transaction_fn` Callback that cannot be called (finding 2); `pasteText` was used to make the view dispatch.
